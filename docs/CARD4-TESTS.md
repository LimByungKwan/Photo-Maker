# 카드 4 — 템플릿 관리

## 저장 항목

- 안정된 UUID, 이름, 생성·수정 시각
- 화면비, 기본 합성/흰색/불러온 이미지 배경 모드
- 배경은 메타데이터를 복사하지 않고 캔버스에서 다시 만든 PNG Blob으로 저장
- 문구 배열: ID, 내용, 위치, 크기, 색, 글꼴, 테두리 여부·색, 자동 맞춤
- 브라우저 IndexedDB의 `card-studio-templates` DB에 저장. 서버로 전송하지 않음.
- 새로고침 시 목록을 읽으며, 다른 브라우저나 사이트 주소에서는 공유되지 않음. 시크릿 창 전체 종료·사이트 데이터 삭제 시 없어질 수 있음.

## 구현 검사

`node tests/templates.test.cjs`: 3개 ID 중복 없음, 수정 ID·생성 시각 유지, 독립 스냅샷, 여러 문구와 Blob 복제, 잘못된 레코드 거부 통과.
기존 글자 배치·PNG/JPEG 캔버스 회귀 검사 및 JS 문법 검사 통과.
사용자 실제 브라우저 검사 완료. C17~C20은 첨부 캡처 확인, C21은 사용자 직접 확인 보고에 근거한다.

## 사용자 확인 순서

1. 서로 다른 문구/비율로 A, B, C 세 템플릿을 새로 저장. 목록 3개 캡처 (C17).
2. A 불러오기: 배경·비율·문구 설정 복원 확인 (C18).
3. A의 이름과 문구를 바꾸고 '불러온 템플릿 덮어쓰기'. 개수가 늘지 않고 A만 변경되는지 확인 (C19).
4. B 삭제 확인. 편집 화면과 A/C가 유지되는지 확인 (C20).
5. 같은 창에서 새로고침. 수정된 A와 C만 남고 다시 불러와 수정 내용이 복원되는지 확인 (C21).

전체 창 재접속 검사는 일반 창에서 진행. 시크릿 창은 열린 상태의 새로고침만 유지 검사.
캡처: 세 개 생성 / A 복원·수정 / B 삭제 후 새로고침 및 A 재불러오기.

잘못된 이름·저장 공간 부족·DB 오류는 안내하고 기존 작업을 삭제하지 않는다. 저장은 트랜잭션 완료 뒤 성공으로 표시하며 삭제는 ID로 처리하고 확인 창을 띄운다.
